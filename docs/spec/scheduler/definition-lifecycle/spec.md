# Storage中心の定義運用

## 合意した動作

- 通常起動ではStorageの運用定義・登録・世代を復元し、入力Blobを再取込しない。初回は定義未登録・停止中として管理画面を利用できる。保存状態の欠損や設定不一致を空状態として初期化しない。
- ブラウザーの自動保存と、SchedulerIdごとの共有下書き1件への明示保存を分ける。共有保存は版比較付き。意味エラーを含む編集中の下書きも保存でき、運用反映は完全検証を必須とする。
- 画面またはUnit/ZIP一式のアップロードから差分・影響を確認して反映する。一式置換であり暗黙マージしない。確認後の変更は競合として再確認する。
- 開始済み・結果不明・個別に変更/追加/保留した世代は旧定義に固定する。通常の未開始予定は新定義へ更新し、取消・解除・消化済みを復活させない。ルート追加は自動確定登録、改名は削除+追加。既存登録の明示条件を保持する。削除したルートの旧世代も閲覧・完了できる。
- 同じSchedulerIdの全体一時停止は後続・判定・リカバリー・手動要求を含む新規開始を止め、起動済みプロセスは止めない。結果回収は続ける。受付と適用完了を区別する。
- 停止状態は再起動・リーダー交代・定義反映で保持する。再開時刻より前の未開始ルートは保留分も見送り、開始済みネットの後続は続行する。停止中の予定を補充で復活させない。
- コピペは同一下書き内で複数選択・子孫・別ネット/ファイルを扱う。内部接続のみ複製し、外部接続の除外と継承差を示す。原文ブロック・未編集属性を維持し、曖昧な参照や種別/階層変換は拒否する。複製ルートは予定なし・保留あり。新ID・名前重複解決・undo/redo・競合を扱う。
- 月表示カレンダーは日付の稼働/休業/個別指定解除、曜日、継承元、参照カレンダーを扱う。実効値は実行エンジンで評価し、日付操作では該当日だけを変更する。別形式Schedule/Calendarと未対応境界は拡張しない。

## 永続化と互換性

保存形式6、編集下書き版9へ進める。旧版の採用ID・世代IDを維持し、定義版の省略は切替前に旧版へ固定する。反映はリーダーのETag付き再開可能ジャーナルで直列化し、部分状態で開始/完成表示しない。世代の生成リビジョンと元の予定枠を区別し、再送・同版反映・切戻しで重複しない。大きい原文/下書き/変更計画は不変Blobへ、Tableには参照を保存する。

全API/実行器を停止して移行する。旧バイナリ混在、認証追加、計画実行登録、切り取り、他ブラウザーへのクリップボード転送は対象外。既存JP1操作の契約とUnknownの扱いを維持する。

## 入出力と操作の境界

- 共有下書きは不変Blob本文とTableのETag付きポインターで保存する。同じ版・同じ本文の応答喪失後の再送は保存済みの結果を返し、別内容の競合は409で拒否する。保存前提の原文を検証するが、編集中の属性値エラーは保存できる。
- 反映確認は現在の登録・世代のETagに加え、時刻経過で通常予定から保護対象へ変わったかも比較する。確認後に影響が変われば再確認を求める。旧取込・Activate経路も同じ反映ジャーナルを通す。
- 保存形式1〜5の移行では、省略定義版、個別保留上書き、定義と異なる監視設定、受付済み登録の版を固定する。途中反映の復旧もSettingsHash一致を先に要求する。初回保留は取消・消化後の再反映で後続へ移さない。
- 削除されたネットの旧図を履歴から開ける。画面は運用版と異なる定義ハッシュを表示していることを案内し、実行回選択時はその回に固定した定義を使う。
- 版9の複製は、コピー時点と貼付時点を検証し、編集履歴内に原文スナップショットを保持する。履歴の1段階で戻せる。座標不足・不正または配置上限で空きがない場合、表現不能な文字コード、参照の不整合を拒否する。切り取り、ルートと子の変換、他ブラウザーへのクリップボード転送は含めない。
- 月表示は1994〜2036年の対応済みUnitカレンダーを既存エンジンで評価する。表示後の編集で古い結果を隠し、再表示を求める。日付だけの指定解除は曜日や月日の指定を消さない。
- 編集POST/PUTのHTTP本文と共有下書き本文は12MiBまで。原文の既存上限（32ファイル、1ファイル2MiB、合計8MiB、1ファイル10000ユニット、深さ64）とは別に、投影・コピー用原文・基点を含む要求の合計も制限する。大きな複製を重ねて上限を超える場合は、出力・再取込で履歴を整理する。

- 運用反映では、世代行に固定する完全名も検証する。UnitPathとRootPathのJSON表記の合計が26000文字を超える定義は、他の世代項目の余白を残すため反映前に拒否する。下書きの保存・ファイル出力と運用可能性の確認を区別する。
- 子世代は最大99行かつ本文の保守的な見積り3MiBで分割保存する。ルートと実行IDの保存を先に、全子が揃った完了印を最後に行い、部分世代の補完とフェンスを維持する。

- 変更前の原文は、貼付による原文再構成後もファイル名の対応で開始時の原文を表示する。追加ファイルに別ファイルの原文を割り当てない。ファイル件数は作業中の原文と追加ファイルから数える。
- ブラウザーの「保存済み」は現在表示している編集履歴の保存完了を表す。編集・undo・redo直後から古い保存完了表示を引き継がず、先行する保存待ちがある間は同じ内容へ戻しても保存完了扱いにしない。
