# 編集・自動保存の追加性能確認

2026-11-07、比較元 `41200f8a8513dab1cee3d06d1f79a16e4a5e630b`。改善後はこの記録を含むコミットの実装。測定時は比較元HEADの作業ツリーへ変更を適用した。PR #8のStorage起動、共有下書き、明示的な運用反映、全体停止、コピペ、月表示カレンダーまで揃った状態を対象とする。[前段の記録](verification.md)と[PR #7の性能記録](../web-ui/performance.md)は過去の入力・条件であり、今回の数値と直接つなげない。

## 条件と計測器

- Linuxの同じクラウド環境、.NET SDK 10.0.403 / Release、Node 24.22.1、Chromium 155、1440×900、ja-JP / Asia/Tokyo。Vite production previewを使用し、ビルドや他の試験と測定を重ねない。
- 単一ネットに200/1000/9000ジョブ。100列の座標と独立した2ノード接続をそれぞれ100/500/4500本持つ。長い依存チェーン、多数ファイル、深いネストを代表しない。原文をローカル下書きとして開き、採用や運用反映は行わない。
- e2e専用Azurite（11300〜11302）、API（5181）、Vite（5174）を測定起動器が生成・終了する。通常Storageやユーザーの下書きは使わない。新しいブラウザーコンテキストで3回のコマンド変更を測定する。
- `paintMs` / `savedMs`はPlaywrightの操作から2フレーム/保存完了待ちまでで、操作探索や試験側の問い合わせを含む。アプリ入力に近い指標として、captureフェーズのinputイベントから2フレームまでを`observations.paintedMs`、保存済み表示へのDOM更新までを`observations.savedMs`へ別記録する。描画と保存は前後する場合がある。
- 保存済み表示だけで完了にせず、新しいIndexedDBトランザクションの完了、実DB内の最後のコマンド、画面再読込後の値も照合する。保存の版比較やキューには計測器から介入しない。
- JSON変換の経過時間、IndexedDB putの同期呼出し時間、readwriteトランザクション全体、CDPのScriptDuration、DOM数、処理後JSヒープを記録する。トランザクション時間はイベントループの待機や読み出しも含み、ディスクI/O時間だけを示さない。ヒープは強制GCなしの観測値であり、ピーク・保持メモリではない。JSON文字数の計測項目は、元の誤解を招くbytesからcharactersへ訂正した（数値は変えない）。sourceBytesはUTF-8の実バイト数。
- 当初の測定は各操作でroleによる探索を行い、9000ジョブの編集・保存全体が7〜9秒となった。入力からの時間を分離し、同じ要素ハンドルと保存状態のCSSセレクターを使う計測器へ修正して、改善前後の両方を測り直した。最初の記録も保持する。

```sh
# SDK探索用のPATH / DOTNET_HOST_PATHを設定し、Releaseビルド後に実行
cd src/JobRunner/clientapp
npm run build
EDITOR_BENCH_PRODUCTION=1 EDITOR_BENCH_LABEL=measurement \
EDITOR_BENCH_OUTPUT=/tmp/editor-interaction.jsonl \
npx playwright test --config playwright.interaction-performance.config.ts
```

改善前の再確認では保存した比較元productionビルドを使用し、アプリのソースやサーバーバイナリを巻き戻さない。`.perf.ts`は通常CIに含めず、絶対時間で合否を判定しない。共有クラウド環境の少数サンプルであり、SLAや最悪時間の保証ではない。

## 改善と維持した契約

- SVGのノード・接続と一覧行を、表示する値だけを受け取るmemo化した部品へ分離。コマンド本文の変更や保存完了表示の更新で、全ノードの中身を再描画しない。
- 操作を図/一覧の親へ委譲し、イベント時に最新のノードとコールバックを参照する。表示が同じため再描画しなかったノードでも、移動で古いコマンドを戻さない。キー操作、Ctrl/Meta複数選択、子ネットを開く操作、接続作成・削除を維持する。
- 接続名の表示で、接続ごとに全ノードを2回探索していた処理をノード名の索引へ変更。多重選択もSetで調べる。改名、座標、種別、選択状態、接続の変化は表示へ反映する。
- IndexedDBの保存形式・全文保存・保存順序・版比較・競合停止・保存済み表示の判定、共有下書きの保存、バックエンドの原文処理、採用・登録・実行データは変更しない。

## 残る制約

全件描画・全件選択肢は維持しており、9000ジョブを単一ネットで扱う待ち時間は解消していない。仮想化やページ分割は、図の全体表示、キーボード操作、複数選択、検索の設計と一緒に扱う必要がある。全文JSON比較と全文IndexedDB保存も残る。差分保存・履歴圧縮・保存の間引きは復旧/競合の契約に影響するため今回変更しない。

実Azure、Windows、Chromium以外、低メモリ端末、複数の重いタブの同時負荷、最大入力の全組合せは未検証。別形式Schedule/Calendar、切り取り、他ブラウザーへのコピー、計画実行登録など既存の対象外機能は追加しない。
