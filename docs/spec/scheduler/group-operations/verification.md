# 検証記録

## 環境と条件

Linux、.NET SDK 10.0.403 / runtime 10.0.14、Node 24.22.1、Azurite 3.35.0、Chromium 155。Storageは専用のテストTable/コンテナーを使用。ブラウザー用Azuriteは11300〜11302、APIは5181、Viteは5174。

性能測定条件と結果は[性能確認](performance.md)を参照。

## 確認対象

- 親停止と子再開、兄弟の独立性、過去予定の見送り、再起動後の停止保持、古い制御版の拒否。
- 改名のID保持と新規停止、開始済み世代の結果回収と後続待機、削除した所属からの再開、完了ルート内のONLY再実行、改名に伴う過去時刻の非再実行。
- 105ネットの再開で、ジャーナル保存・部分バッチ・制御保存・完了保存直後に実Storage応答を失わせる。件数/日数両方式、先読み期間を超える停止。新規105グループの停止行の最初の99行保存直後にも中断して復旧。
- UTF-8/UTF-16/Shift_JISのZIP追加・置換、独立ファイル、内部jcの追従、外部参照・祖先継承・名前衝突・選択外定義の混入の拒否。有効CP932の原文保持と、.NETが無効とする87 90の入力拒否。
- 旧保存形式1〜6を無変更で拒否。旧データ移行はユーザー指定で対象外。
- ブラウザーの追加・undo・再読込、運用データ不変、停止元表示と操作ID/期待版の送信。既存の複数タブ競合・保存表示・遅延応答・再取込試験も全体検証に含める。

## 最終結果

- Releaseビルド成功、.NET全559件成功（`groups-final-all.trx`、2分44秒）。
- Vitest 46件、Playwright 64件成功。lint・Prettier確認・TypeScript/Viteビルド成功。
- 最新コミットのCIはPRのChecksで確認する。実Azure/Windows/実JP1の成功を意味しない。

## 実行経過

- 初回の全体確認は553件中550成功。操作の省略項目をJSONへ追加したことによるハッシュ差は、null項目の出力を省略して修正。ジャーナル参照保存前の中断2ケースは未適用であるため、適用時点の境界を期待するようテストを修正。
- 次の全体確認554件は全成功。その後、ONLY再実行・新規グループの部分反映・改名後の過去予定の回帰を追加。
- 最新557件では556成功、1件が既存のPublicationWriteBoundaryTestsの再起動時Blob読み出しで5秒通信タイムアウト。ブラウザー試験との並行中だったため、該当22ケースを分離して再試験し、全成功（29秒）。タイムアウト値やアサーションは緩めない。
- ブラウザー新規試験の初回は1成功/1失敗。再読込後は監視画面へ戻るため、編集画面を開き直す操作を追加。全64件が成功（5.4分）。保存待機や製品の保存制御は変更していない。

- フロントエンドのlint・Prettier確認・TypeScript/Viteビルド・Vitest 46件が成功。
- 改名を繰り返した個別保留の未来枠と、自動登録解除の維持も追加回帰に含める。

## 制約

実Azure、Windows、実JP1との接続は未検証。旧データの変換・グループ自身の階層移動は対象外。祖先の継承属性は上書きの有無にかかわらずZIP出力を保守的に拒否する。同じBlob名の複数マッピングはローカル入力の重複名制限に従い拒否する。原文の32ファイル・各2MiB・合計8MiB・10000ユニット制限は、処理メモリの上限を保証するものではない。
