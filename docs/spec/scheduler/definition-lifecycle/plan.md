## 編集操作の追加性能確認

基点は `41200f8`。主要な定義編集・共有保存・明示反映・全体停止が揃った状態で、単一ネット200/1000/9000ジョブをproductionビルドで再測定する。独立したAzuriteを使用し、採用済みのユーザーデータは扱わない。

1. 読込、選択、入力から描画、現在の入力の保存完了を分離し、IndexedDBのトランザクション・put・JSON変換・DOM・JSヒープを測る。既存計測器の操作探索時間も含まれるため、入力イベント起点の時間と区別する。
2. 測定で確認したボトルネックを対象に、不要な描画や繰り返し探索を整理する。保存形式、保存順序、版比較、競合停止、原文のレンダリング、運用データは維持する。大きな保存方式の変更はこの改善に含めない。
3. 同じ測定器と入力で比較し、選択・改名・座標・接続・種別・undo/redo・遅い保存・別タブ競合・再読込を回帰検証する。変更しないノードの再描画だけを省き、操作後の最新値を表示する。
4. 数値と未改善部分を検証記録へ残す。絶対時間をCIの合否にせず、既存回帰と最新SHAのCIを確認する。PRの現在の状態を尊重し、マージしない。
