# 実装計画

1. グループの固定IDを不変カタログへ保存し、採用・登録・世代から参照する。新規環境は形式7を使用し、旧データ移行は行わない。
2. グループ停止・再開を既存の操作ジャーナルとリーダーの条件付き更新へ統合する。実行開始と過去予定の生成で所属グループの制御を評価する。
3. 運用反映でグループIDの対応と新規停止を同じジャーナルに含める。画面へ実効停止と継承を返す。
4. 原文保持の編集処理を使い、依存関係を検証したグループZIPの出力と追加・置換を実装する。既存の下書き履歴・競合制御を使う。
5. グループ選択・停止再開・入出力のUI、OpenAPIと生成型を更新する。
6. 階層・世代復旧・書込中断・旧形式拒否・原文保持・再取込・UI保存の回帰を追加する。大規模グループの測定、全体検証、最新SHAのCI確認を行い、1つのドラフトPRにまとめる。

カタログを定義原文のハッシュから分離する理由は、JP1定義ファイルへ運用IDを書き込まず、同じ原文でも削除後の再作成を区別するため。世代は不変カタログを参照し、現在の階層変更で過去の所属を解釈し直さない。
