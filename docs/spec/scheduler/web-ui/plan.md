# 実装・検証計画
1. UI向け読取APIを追加し、既存の固定定義・状態変換・操作キューを再利用する。保存形式は変更しない。
2. OpenAPI出力とaspida生成を整備し、useAspidaSWRでReactへ接続する。
3. 定義座標とSVGの閲覧用図、階層・世代選択、予定変更を実装する。
4. 開発ホストによるViteプロセス管理、publish時ビルド、CIを整備する。
5. API・Vitest・実APIを使用したPlaywright・既存全体試験を実施する。画面イメージを保存し目視確認する。

図はJP1定義のel座標を必須とし、SVGで描画する。ELKは削除する。月間一覧は確定予定・実績の読み取り専用APIとuseAspidaSWRで実装する。

実機確認でSpaProxyは最初のアクセス前にViteを起動しなかったため、Developmentかつ開発プロファイルで有効になるHostedServiceからnpm run devを起動する。ホスト終了時は子プロセスも終了する。

実装と検証の結果は[検証記録](verification.md)に記載する。画面イメージは[仕様](spec.md)から参照する。

## 読み取り性能の改善

同じ応答内で繰り返している実行回・接続・試行の検索を索引にまとめ、状態変換を一括化する。月間一覧は最初にルート別に分類し、月内に対象がない場合は試行一覧の取得を省く。日時の書式オブジェクトと画面の検索用データも再利用する。状態や操作結果を要求間でキャッシュせず、5秒更新・固定定義・退避済み結果・月境界の意味を維持する。

変更前後の同じ入力で処理時間と割当量を測り、複数ルートの状態分離、空の月の読み取り、既存HTTP契約とPlaywrightの受入条件を再検証する。READMEには保存済みの監視・月間画面を埋め込む。

## 実行ログ・絞り込みの追加

1. 既存の退避履歴読取を再利用し、所属を検証する試行一覧と16チャンク上限のログページAPIを追加。保存方式・既存APIは維持する。実HTTPで履歴と境界を検証する。
2. OpenAPIとaspidaを再生成し、useAspidaSWRで必要な対象だけ取得する。試行を固定した下部パネルと64チャンク上限の表示モデルを実装する。
3. 共通の状態選択、図の一覧と薄表示、月間の祖先保持を追加する。フィルター変更とログ対象を独立させる。
4. .NET全体、型/整形/解析、Vitest、実APIのPlaywrightを実施し、README・仕様画像・検証記録を更新する。先のPR #5がマージ済みのため、最新mainから新しいドラフトPRを作成する。

URLへの選択状態保存と日時入力の改善は今回含めない。ログ本文は固定サイズのページを読み、終了後の本文ポーリングを止める。初回の末尾探索はBlob名の列挙のみを行う。

## 定義編集とダウンロード

1. 保存済みmanifestと原文を検証して読み出す。既存パーサーに保存対象外の構文位置を追加し、原文への局所置換で編集する。永続モデル・採用・予定・実行の保存方式は変更しない。
2. 現在の定義の編集用投影、下書き検証、ファイル出力の独自UI APIを追加。既存の全ファイル検証を再利用し、Swaggerからaspidaを再生成する。
3. SVG・プロパティフォーム、ジョブ追加削除、接続、配置、undo/redo、読取専用プレビューを追加。IndexedDBへ版を固定して自動保存し、採用版変更は警告する。
4. 原文バイト同一性、引用符、日本語、改行/BOM/文字コード、複数ファイル、参照/循環/座標、運用データ不変を検証する。Playwrightでドラッグ、フォーム、復元、ダウンロードと既存画面を確認する。
5. READMEと画像・検証記録を更新し、新しいドラフトPRを作成して最新コミットのCIを確認する。

## 判定ジョブ編集の追加

1. 種別ごとの編集属性と投影の版を追加し、旧要求を従来の契約で扱う。原文の局所置換と既存意味検証を再利用する。
2. 指定した保存済み版の読取を用意し、旧下書きの欠けた判定属性だけを補う。保存競合・原文取得失敗時の非破壊を確認する。
3. 判定方式別の入力、jdj/rjdj追加削除、名前と接続の編集、条件変更の確認を実装する。
4. 原文保持・旧下書き・実HTTPの非変更・ブラウザー操作を検証し、既存全体試験と最新コミットのCIを確認する。同じドラフトPRへ反映する。

次の新規ネット、スケジュール・カレンダー、ローカルファイルはこの段階の確認後に進める。一通りの編集が揃った最後に性能の計測、改善候補の評価、リファクタと回帰検証を行う。

## ネット階層編集の追加

1. 原文ファイルに属するルートと追加可能な配置先を投影し、旧要求を維持する版3を追加する。
2. 安定IDで階層と所有ファイルを検証し、ネット構造を局所編集した原文へ既存のジョブ・接続・配置編集を適用する。全体の再シリアライズはしない。
3. ルート作成、子ネット作成、現在のネットの名前変更と子孫削除、編集後のパス表示を追加する。旧下書きの移行は元版と保存世代比較を使う。
4. 原文・所属・参照・移動拒否・安全な初期予定・運用データ不変を.NETで、親子編集・旧下書き・競合・出力再解析をPlaywrightで検証し、同じドラフトPRの最新CIまで確認する。

階層移動、グループ自体の編集、別ファイルのTargetPathを連動変更する操作、新規ファイル作成は含めない。既存取込が空ファイルを拒否する制約を保持する。

5. 原文保持・境界・旧下書き・競合・再取込・運用データ不変を確認し、全CIを確認して同じドラフトPRへ反映する。
