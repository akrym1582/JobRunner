# グループ操作の負荷確認

Linux / .NET 10.0.14 / 4論理CPU。Release、500グループ＋500ネットと4000グループ＋4000ネットを一つのUTF-8原文に配置。ネットは予定なし。原文サイズは19,390文字と158,890文字。DB/HTTP/ブラウザー描画はこの測定に含めない。

`JobRunner.EditorBenchmarks group-operations groups <500または4000> 1` を使用。JITウォームアップ後、各試行前にGCし、3回の中央値を記録。下記は他の検証を同時実行しない測定。エクスポートは先頭グループ、インポートはそれを別名で追加する。原文の全体検証・再投影は処理に含む。

| グループ数 | 処理 | 中央値 ms | スレッド割当 MiB | 最大プロセスRSS MiB |
| --- | --- | ---: | ---: | ---: |
| 500 | 所属カタログ作成 | 0.46 | 0.18 | 74.86 |
| 500 | グループZIP出力 | 86.12 | 26.63 | 104.12 |
| 500 | グループZIP追加 | 78.55 | 40.87 | 170.90 |
| 4000 | 所属カタログ作成 | 3.09 | 1.13 | 171.79 |
| 4000 | グループZIP出力 | 545.72 | 202.73 | 237.66 |
| 4000 | グループZIP追加 | 803.30 | 309.37 | 298.01 |

IDの重複検査・既存ID照合・反映時の旧パス照合は集合で行う。実行判定では不変カタログをキャッシュし、完全名の祖先だけを探索する。全グループを各ジョブで走査しない。停止状態のTable列挙はTick単位で行い、ジョブごとのStorage取得はしない。

残る主な費用は原文全体の検証・再投影で、4000グループの追加は約309MiBの割当を伴う。意味検証を省略する最適化は行わない。停止状態照会は未完了の旧所属を発見するため世代行を読む。大量の履歴、巨大属性、複数利用者の同時操作、および4000グループのブラウザー描画時間は未計測。入力サイズ制限はピークメモリの保証ではない。
