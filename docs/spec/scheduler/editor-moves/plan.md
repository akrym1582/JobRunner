# 実装と検証の対応

1. 原文編集は既存Documentのバイト範囲置換を再利用し、移動ブロックの生バイト挿入を追加する。参照編集を先に確定してから抽出・挿入し、独立ファイルの配置だけを追従する。別文字コードではブロックだけ厳密変換し、前後に改行を置く。対応: EditorMoveTests、Playwright移動・履歴試験。
2. ZIPの構造・サイズ検査は維持し、参照不足だけを編集用の検証で許可する。外部jcを保持し内部jcだけを書き換える。完全検証は運用反映と予定試算の境界に残す。対応: GroupPackageTests、EditorMoveTests、Playwright未解決参照と反映拒否。
3. カタログ版2のルートIDで改名・移動を追跡する。保存形式8として旧形式を拒否し、既存の99行変更計画・生成復旧を再利用する。同名パスによる従来の排他も保持する。対応: RootMoveRuntimeTests、PublicationWriteBoundaryTestsの実書込み中断。
4. GUIは候補の診断確認後に一つの履歴へ適用する。ファイルは識別情報で照合し、新規ファイルを重複表示しない。所属版を固定して、配置反映後の古い下書きからIDを黙って再生成することを防ぐ。対応: Vitest、Playwright、共有保存・競合の既存回帰。
5. API個別確定登録のカーソル・期間・除外を自動登録へ暗黙変換する意味は採用しない。下書き移動は保持し、運用反映前に登録の確認・解除・再登録を案内する。対応: RootMoveRuntimeTestsの拒否・条件保持・解除後の反映。

全体試験と最終CIを確認し、一つのドラフトPRとして提供する。旧運用データ移行・実Azure/Windows/実JP1検証は対象に含めない。

## ジョブ・子ネットの選択移動

1. 同じ親の複数選択と移動先ネットIDを検証する専用APIを追加し、既存の原文バイト編集と下書き投影を再利用する。
2. 内部接続・配置を移し、外部接続を確認付きで切断する。候補全体を検証し、曖昧な補完をしない。
3. 現在の画面選択から候補を作り、古い応答・競合を既存の適用経路で保護する。
4. 編集・原文・再取込、ブラウザー保存/undo/redo/競合、日数/件数の組合せ運用と実書込み中断を検証する。
5. 全体検証、API生成物、push/PRの最新CIを確認し、一つのドラフトPRにする。旧データ移行やマージはしない。
